## 5. Pass 3 — Route security

### 5.1 What is correct — stated so a later run does not re-derive it

- **The unauthenticated-plus-unbounded-cost class is closed.** `/api/tts/speak`
  (`tts.js:264`) and `/api/ai/brief` (`ai.js:351`) are both wrapped in
  `loopbackOnly(...)`. So are the display, house, list and recipe write lanes.
- **HA proxy leak is guarded**: `pathFilter: haMediaPathFilter` is present on the
  `/api/image_proxy` and `/api/camera_proxy` mounts (`server.js:289`), so the
  `HA_TOKEN` cannot be attached to an arbitrary path.
- **CSRF**: `blockCrossOriginWrites(allowed)` is mounted app-wide *before*
  `express.json()`, so a rejected cross-origin write is never even parsed.
- **Rate limiting**: 600 req/min on `/api`, `skip: isLoopback`, `trust proxy` explicitly
  false so the limiter keys on the real socket.
- **Admin**: HTTP Basic + `crypto.timingSafeEqual`, and it **fails closed** — with no
  `ADMIN_PASSWORD` set the routes return 403 rather than opening.
- **No `eval`, no `new Function`** in shipped code. The only `child_process` uses are
  `execFile` with a fixed binary and an array of args (`xset` in `display.js`, `ffmpeg`
  in `liveMotion.js`) — no shell, so no injection surface.

### 9.1 F1 — HIGH — 31 of 80 feature flags are inert on the surface `/` serves

`src/js/config.js` declares **80 boolean flags** (75 `true`, 5 `false`). Every one has a
production reader, and every one reaches a bundle — so no flag is dead in the ordinary
sense. The problem is *which* bundle.

Method: walk the real module graph from `src/v3/index.html` (99 files) and from
`src/index.html` (147 files), then ask of each flag whether any file that reads it falls
inside V3's closure. Result: **31 flags have no reader V3 can reach.** For 28 of them the
flag name appears **zero times** in `dist/assets/v3-*.js` while appearing 1–9 times in
the incumbent's bundle. The 3 non-zero hits were inspected individually and are all
coincidental substrings — `backgroundImage`, the CSS class `cell__clock`, and
`config.homeAssistant.mediaPlayer` (a config *section*, not the flag).

```
presenceRuntime  attentionEngine  ambientAtmospherics  ambientSubstrate  heroType
ambientClock     leanInStack      arrivalCard          arrivalBottom     ambientMemory
bareTopRow       bareHero         awakeGround          livingAccent      awakePhotoDissolve

skyRamp          nightSky         atmoTextures         recipePanel       voiceRail
temporalSpine    ambientArchive   archiveMotionLoop    background        clock

```

Twenty-six of the thirty-one are gated **only** in `src/js/core/app.js` — the incumbent
bootstrap, which V3 does not import.

**What this does and does not mean.** It does *not* mean these features are missing from
the wall; V3 reimplements several of them (its own substrate, its own archive) without a
flag gate. It means **the flag is not the lever.** `CLAUDE.md` states that flipping a
flag off *is* the rollback path and that every flag must be cleanly reversible. For
these 31, on the surface that is actually serving, **that rollback path does not exist** —
setting `nightSky: false` and rebuilding changes nothing on the glass. A future session
reaching for a flag flip as its emergency lever would find it inert, and the flag-off
half of `/flag-flip`'s reversibility check would pass while proving nothing.

*Fix, in order of value:* (a) mark each of the 31 in `config.js` with its surface, so the
file stops implying a lever it does not have; (b) for any of them still wanted as a live
lever on V3, wire the gate into the V3 module that owns the behaviour; (c) retire the
ones whose feature V3 does not have at all. **~4 h for (a) alone**, which is the part
worth doing first because it prevents the wrong flip.
